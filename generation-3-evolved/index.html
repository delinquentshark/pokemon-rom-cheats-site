Pokémon Generation 3 Evolved Field Guide

Cheat codes for the ROM hack Pokémon Generation 3 Evolved (version 1.0.20), worked out from the game itself and tested in the mGBA emulator, plus look-ups for its items, moves, abilities, every species (with sprites, base stats and evolutions) and the wild Pokémon of Kanto, the Sevii Islands and Hoenn.

Using a code in mGBA

  1. Open the cheats window. With the game running in mGBA, pick Tools → Cheats…
  2. Paste it and add it. Press Copy on a code in this guide, paste it into the box that says Enter codes here… and click Add New Code. Leave the code type on Autodetect.
  3. Tick it on, untick it off. A new code starts ticked, so it's already working. Untick it to switch it off. Double-click its name, (untitled), to rename it.

Before you start

  • Check it's the right game file. In mGBA, with the game running, open File → ROM info…: CRC32 should say a459e886. Anything else is a different version of Pokémon Generation 3 Evolved: the codes won't work and could crash the game.
  • Back up your save. Copy the .sav file next to your ROM somewhere safe before trying codes. Every code here was tested for save damage, but a backup costs nothing.
  • Add each code on its own so you can switch them on and off separately. Don't add a "master code": mGBA doesn't need one, and one made for another game stops these codes working. If you already added one, remove all your cheats and restart mGBA.
  • Codes only work while they're ticked. Whatever you get while one is on (items, money, Pokémon, moves) is normal game data, so it stays after you untick the code and save.
  • Untick a code before you remove it. If you press Remove on a code that's still ticked, its effect can keep running until you restart mGBA.
  • mGBA remembers your codes, and whether each one is ticked, the next time you open the game. Untick the ones you aren't using.
  • Your game file is never changed. Codes change the game only in mGBA's memory, and only while they're ticked.

What's different in this game

Generation 3 Evolved is built on pokeemerald-expansion (a modern Emerald decompilation with every generation's Pokémon, moves and abilities), set up as a FireRed game: you start in Kanto, then go on to the Sevii Islands and Hoenn. Its code and data sit in different places from Emerald's, FireRed's and other expansion hacks', so use only the codes on this page with it.

  • Every generation's Pokémon. 1575 species entries, 555 of them forms (Alolan, Galarian, Hisuian and Paldean forms, Megas, Gigantamax and more). The Species tab lists them all, with sprites.
  • TMs teach through the storage screen. Using a TM (or talking to a move tutor) opens the Pokémon storage screen, where you pick who learns it, and TMs aren't used up. Any Pokémon can learn any TM covers the tutors too.
  • No PC item storage. This game's save has no room for a PC item box, so Any item ×999 puts the items straight into your Bag when you open it.
  • Natures, three abilities and hidden ones. 1280 species have a hidden ability, and wild Pokémon sometimes come with it on their own; Pick the ability makes it every time.
  • Roaming legendaries. 39 Pokémon (legendaries, Mythicals and Ultra Beasts) can roam; some keep to a few places, which the Encounter map lists, and each one's card says it roams.
  • Seven Bag pockets: Items, Medicine, Berries, TMs & HMs, Poké Balls, Power Ups, Key Items.

How the codes were made and tested

Every code was worked out from this ROM. The expansion's source (version 1.16.3, built as FireRed) was compiled for reference, and its functions were matched to the ROM's by their instructions, which found most of the game's functions and tables; the rest were found from the code that uses them. Each code changes the spot where the game decides a thing (a new Pokémon's personality and ability, the money it stores, the move a TM teaches…) by patching instructions in mGBA's copy of the ROM. The catching codes and the item code add a small routine of their own in the ROM's empty space; the game still builds every Pokémon and item itself, checksum and all.

Every code was then run in a headless build of mGBA 0.10.5, driving the game like a player: walks through the grass, the game's own event scripts, a Poké Mart, the Bag, the storage screen, real battles and real Poké Ball throws. After each test the result was read from the game's memory, and anything saved was checked by saving with the codes on, unticking everything, resetting and pressing Continue: the Pokémon, items and money had to come back unchanged, with a valid checksum, no Bad Egg, and the game loading straight into the overworld. The ROM file's SHA-1 was the same after all testing.

Code formats

Encrypted
The codes you copy on this page are encrypted Action Replay (PAR v3) codes. mGBA reads them as Autodetect or Action Replay MAX.
Raw
Each code's raw (decrypted) form is in the Under the hood section of its tab, with the addresses it changes. Raw codes need Autodetect. Most are ROM patches: 00000000 18aaaaaa + 0000vvvv 00000000 puts the 16-bit value vvvv at address 0x08000000 + aaaaaa × 2.
Long codes
The species, nature, gender and ability codes are about 330 lines each, because each one carries the whole routine they share. Paste the whole code into one Add New Code. Ticking several of them at once is fine: they put the same routine in the same place, and mGBA keeps it while any of them is ticked.
In the browser
The page builds each code from your choices in codes.ts, a copy of the Python generator used for the tests. A check runs both on every code the page can make (98,902 codes, 1,775,865 lines: every species in every version, every nature, gender, ability and IV code, every TM and move pair, every item, and the fixed codes), and they match exactly. That check runs in Node.js. The page itself was tested in Chromium at desktop and phone widths, not in other browsers.
Remove while ticked
Unticking a code restores the original instructions. Removing a code that's still ticked leaves its patch in mGBA's memory (tested), so untick first; restarting mGBA clears it.

Why not a RAM write
This game has no PC item storage (its save keeps no PC item slots), and the Bag's quantities are stored XOR'd with the save's key (SaveBlock2 + 0xB0), so writing a number into memory wouldn't give a valid item.
0x08DA3C4C
The Start menu's BAG entry: a pointer to StartMenuBagCallback (0x0821AE75), which the menu calls every frame until the screen has faded out. The code points it at a routine in the ROM's empty space (asm/bag_item.s, 60 bytes at 0x09FF8000, the item ID right after it).
The routine
Asks the game's CountTotalItemQuantityInBag (0x08170454) how many there are, and if fewer than 999, gives the rest with AddBagItem (0x081706A4), which puts them in the item's own pocket, key and all (and does nothing if the pocket is full). Then it runs the real callback, so the Bag opens as usual.
0x08778E04
Item table (gItemsInfo): 901 entries of 48 bytes; names and pockets on this page come from it. The 882 items listed are the ones with a name.

Money, coins and Battle Points

Money (SaveBlock1 + 0x490) and coins (+0x494) are stored XOR'd with the save's key (SaveBlock2 + 0xB0), so a plain memory write can't set them. The codes change the game's own money and coin functions instead, and the game stores the maximum itself the next time it adds or takes some, key and all.

Money
GetMoney (0x08193F40) returns 99,999,999 (the literal already in AddMoney's pool); IsEnoughMoney (0x08193F68) and the "enough for the cost in var 0x8005?" special (0x08193FC4) always say yes; AddMoney (0x08193F80) and RemoveMoney (0x08193FA8) both branch to AddMoney's "cap at 99,999,999" store; the "take the cost in var 0x8005" special (0x08193FF0) returns at once.
Coins
GetCoins (0x080FA01C) returns 9,999; AddCoins (0x080FA06C, 0x080FA07A) stores 9,999; RemoveCoins (0x080FA0CE–0x080FA0D2) stores 9,999.
Battle Points
SaveBlock2 + 0x9E8, a plain u16. One type 0x42 line writes 9,999 there through gSaveBlock2Ptr (0x030052DC) every frame.

How each code works

Raw forms need Autodetect. For the codes that come in versions, the raw form shown is the version picked at the top of this tab. In the raw templates, the highlighted value is the one you'd change.

Always shiny

This game decides a Pokémon's shininess once, when it's made, and stores it with the Pokémon (a "shiny" bit in its data, next to the usual shiny value). CreateBoxMon (0x081CBB20) makes every Pokémon; for one with you as its original trainer (wild, one-off battles, gifts, Eggs) it asks ComputePlayerShinyOdds (0x081C4328: the shiny odds, the Shiny Charm and the chain rerolls) at 0x081CBCF6. The first two patches turn that call into movs r0, #1 / nop: "yes". A gift's script can also set shininess itself after the Pokémon is made (always, never, or the usual roll); the third patch (0x0820DD40, cmp r7, #0 → cmp r0, r0) makes that "always". Trainers' Pokémon and in-game trades take other branches. The personality isn't touched.

The routine the species, nature, gender and ability codes share

These four codes add the same routine (asm/catch.s, 296 bytes at 0x09FF0000, in the ROM's empty space). It has two entry points, and each code adds the jump to the one it needs (ldr r4, [pc] / bx r4 and the address, in place of a few of the game's instructions, which the routine runs itself before jumping back):

  • 0x081CBB22, the start of CreateBoxMon: the species, nature and gender (species, nature and gender codes).
  • 0x081CBCB4, where CreateBoxMon sets the ability number (ability code).

Markers. CreateBoxMon is told whose Pokémon it is making by a "trainer ID" argument: 0 means you. A marker changes that 0, at one call, to 3 (wild), 4 (one-off) or 5 (gift); CreateBoxMon still treats those as you. The routine acts only on a call carrying a marker, and reads a small table at 0x09FF0400, one slot for each kind. The Wild only version marks CreateWildMon's call (0x0824534A)Wild + one-off version marks CreateWildMon's call (0x0824534A), the setwildbattle command's three (0x0820D5BE, 0x0820D65A, 0x0820D6AA) and the legendaries' event special 0x201 (0x081CC7CA)broadest version marks those and the givemon command's call (0x0820DD2C) and fills the wild slotthose two slotsall three slots.

What the routine does (each table entry 0xFFFF = not asked): a species replaces the one passed in, so everything after (the Pokédex, the level, the game's own rules) sees your pick; for nature and gender it searches for a personality that has the ones asked for and keeps the one not asked for from the game's own first draw, keeping the personality's shiny value in the same block of 8, so a Pokémon that would have been shiny still is and one that wouldn't still isn't; the ability is stored as the ability number asked for, after the game has set its own. Species that are always one gender or genderless skip the gender test. The ability code also turns off two places that set the ability number again later: CreateWildMon's own hidden-ability roll (0x0824536C) and, in the gift version, a gift script's ability (0x0820DE0C). The game then builds the Pokémon itself, checksum and all.

How each code works

Change what a TM teaches

00000000 183E0312 0000MMMM 00000000

The game looks up each TM's move in a table at 0x087C0624, 2 bytes per TM and HM item (TM01 is item 582, TM100 is 681, HM01 is 682, HM09 is 690), through ItemIdToBattleMoveId (0x081AF96C). The first line of the code points at the chosen TM's 2 bytes and the second line is the move ID to put there. While the code is ticked, mGBA writes that move ID into its copy of the game; when you untick it, mGBA puts the original 2 bytes back. The Bag and the teaching read that one entry, which is why they change together. Who can learn it is checked against the move itself (the species' list of teachable moves), so it follows the new move.

MMMM is the move's 4-digit hex ID from the list; the first line depends on the TM picked in the card.

Where the data comes from

0x087CA828
gSpeciesInfo (pointed at by the game's ROM header, +0xBC), 0x108 bytes per species: base stats +0 to +5 (HP, Attack, Defense, Speed, Sp. Atk, Sp. Def), the two types at +6 and +7 (the same one twice for a single type), catch rate +8, gender ratio +0x12 (0 male only, 254 female only, 255 genderless), the three abilities at +0x18, the name at +0x2C, the national Pokédex number at +0x3C, flags at +0x8C (legendary, Mythical, Ultra Beast, Paradox, and the form kind: Mega, Primal, Alolan…), the learnsets at +0x94, +0x98 and +0x9C, the evolutions at +0xA0 and the form table at +0xA4.
Forms
555 entries share their name with another (a regional form, a Mega, a Gigantamax…). They're species of their own here, with their own stats, types, abilities and codes. A card lists the species' Forms under its evolution family (the 135 battle forms, Mega, Primal, Ultra Burst and Gigantamax, marked Battle only), each a button that switches the card to it.
Only by evolution
367 species are met nowhere themselves (no wild table, gift, Egg, one-off battle or roaming slot) but their line starts with one that is: the card says Only by evolution and gives the steps from that one.
Sprites
The front picture's first frame (gSpeciesInfo +0x58) and the back picture (+0x5C) in the species' own colours (+0x60; the shiny ones +0x64). The pictures are packed in the expansion's own format, which the GBA itself can't unpack, so each was unpacked by the game's own routine (DecompressDataWithHeaderWram, 0x08114EB0) in mGBA. Entry 1172 has no picture.
Gender
The card's split is the game's own rule: female when the personality's lowest byte is below the species' ratio.
Evolutions
gSpeciesInfo +0xA0: a list per species of {method, parameter, species, conditions} (536 species evolve). The card's wording follows the method (Level N, Use X, Level N (in a battle), Spin around) and its conditions (a time of day, friendship, a held item, a move it knows, a place, the weather, a Pokémon in the party, the Attack/Defense split…). This hack added a condition of its own, with N coins in the Coin Case (checked with GetCoins in 0x081C9ED8).
