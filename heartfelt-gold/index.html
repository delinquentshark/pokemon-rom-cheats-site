Heartfelt Gold Field Guide

Cheat codes for the Nintendo DS Pokémon ROM hack Pokémon Heartfelt Gold (built with hg-engine on the US HeartGold), worked out from the game itself and tested in the melonDS emulator, plus look-ups for moves, abilities, species, learnsets and wild encounters.

Your game version:

Every code on this page switches to match, on every tab. Not sure? In melonDS open System → ROM info: ARM9 size is 1122040 on 1.0.9 and 2389960 on 1.0.4. The 1.0.9 codes do nothing on 1.0.4; 1.0.4's TM and catching codes crash or break 1.0.9.

Using a code in melonDS

  1. Open the cheat editor. With the game running in melonDS, pick System → Setup cheat codes.
  2. Paste it and save it. Click New AR code, type a name in Name, press Copy on a code in this guide and paste it into the Code box, then click Save.
  3. Tick it, then close. Tick the box next to the code's name in the list on the left, then click Close. (The Enabled box above the code doesn't stay ticked when you save.)
  4. Switch cheats on. Pick System → Enable cheats. If it was already ticked, pick it twice, off and on again: melonDS only reads your codes when cheats are switched on or the game starts. Do the same after you untick or delete a code.

Before you start

  • Check it's the right game file. In melonDS, with the game running, open System → ROM info: Game code should say IPKE and ARM9 size 1122040 bytes (1.0.9) or 2389960 bytes (1.0.4), and the title screen should say HeartFelt Gold. Pick that version in the bar at the top of the page. Anything else is a different version of Heartfelt Gold: the codes won't work, and the wrong version's codes could crash the game.
  • Back up your save. Copy the .sav file next to your ROM somewhere safe before trying codes. Every code here was tested for save damage, but a backup costs nothing.
  • Add each code on its own so you can switch them on and off separately. You don't need a "master code": melonDS doesn't use one, and these codes were tested without one.
  • Codes only work while they're ticked and cheats are on. Whatever you get while one is on (items, money, Pokémon) is normal game data, so it stays after you untick the code and save.
  • After adding, ticking, unticking or deleting a code, switch cheats off and on (System → Enable cheats, twice). Until then melonDS keeps running the codes as they were. Switching Enable cheats off stops every code at once.
  • melonDS remembers your codes, and whether each one is ticked, in a .mch file next to your game, and it remembers whether Enable cheats is on. Untick the ones you aren't using.
  • Your game file is never changed. Codes change the game only in melonDS's memory, and only while they're on.

Pokémon HeartFelt Gold (as its title screen writes it): a ROM hack of the US HeartGold (game code IPKE) built with hg-engine, which adds the Pokémon, moves, abilities and items of later generations in new overlays (129, 130 and 131) and replaces many of the game's functions with its own. How the codes were made and tested

Every code was worked out from this ROM: its code (the ARM9 program and its overlays, hg-engine's included) was disassembled to find where the game makes a new Pokémon, keeps your money and builds your Bag, and each code changes the game at that spot. Codes that change a new Pokémon don't rewrite it afterwards: they copy a small routine of their own into a free part of the DS's memory and point the game's own creation function at it, so the game still builds a valid Pokémon itself (its checksum, stats and ability). Each routine checks every frame that its code is still on, so a code stops acting as soon as you switch it off.

Every code was then run in melonDS 1.1 (a headless build of melonDS's own core), driving the game like a player: walking into wild battles on Route 29, picking a starter in Professor Elm's lab, buying in the Cherrygrove Poké Mart, opening the Bag, teaching TMs, throwing Poké Balls. After each test the result was read from the game's memory, and anything saved was checked by saving with the codes on, switching every code off, turning the game off and on and pressing Continue: the Pokémon, items and money had to come back unchanged and valid, with the game back in the overworld. Every code was also loaded through melonDS's own cheat-file reader to check it writes exactly what it should. The ROM file's SHA-1 was the same after all testing.

The steps in Using a code in melonDS are melonDS 1.1's own, the same for every melonDS guide on this site; they were checked in the real melonDS 1.1 program with Origin HeartGold. For this game the codes ran in the same melonDS core without its window, loaded through the same cheat-file reader.

Plain

The routine
The first lines (E23D6200 00000044 and the nine after it) copy a 68-byte routine into free memory at 0x023D6200. hg-engine replaced the game's CreateBagView, the function that builds the Bag screen for the menu's BAG (and for giving an item, selling…), with its own: the game's entry at 0x02078644 is ldr r3, [pc] / bx r3 and the address of hg-engine's version. The line 02078648 023D6201 points that address at the routine. Each time the game builds the Bag screen, the routine asks the game's own Bag_GetQuantity how many you have and adds the rest with the game's own Bag_AddItem, the function picking up an item uses, so the item lands in its own pocket the normal way, then goes on to hg-engine's function. Bag_AddItem adds nothing when the pocket has no free slot, or when the total would pass the item's limit.
Still on?
The four D… lines before the last copy the DS's frame counter (0x027FFC3C) and the item and quantity into a small table at 0x023D6340, every frame. The routine adds nothing unless that copy is less than 9 frames old, so once the code is off it stops, even though the address stays pointed at it until the game is reset.
Free memory
0x023D6000–0x023D7FFF lies between the end of hg-engine's battle overlay 130 (0x023D58540x023D5EC4 in 1.0.9) and the start of its overlay 129 (0x023D8000, always loaded), above every heap the game makes (they end at 0x023C0000). Filled with a random pattern and then played through (a wild battle, the battle Bag, the Bag, the party and summary screens, saving, walking, buying in a Mart), nothing in the game changed a byte of it (Start here tab, "These checks cover every code").

How each code works

The codes are plain Action Replay DS lines; the raw form is the code itself. For the codes that come in versions, the one shown is the version picked at the top of this tab. The highlighted value is the one you'd change.

The routine every catching code shares

hg-engine replaced the game's CreateBoxMon, the function that builds every new Pokémon, with its own (CreateBoxMonData, in overlay 129 at 0x023DA8B40x023DAA78); the game's own entry at 0x0206DED0 now just calls it. The six codes for new Pokémon all start with the same lines: E23D6000 000001EC and the 62 after it copy a 492-byte routine into free memory at 0x023D6000 (see "Free memory" on the Items tab), and the next two lines point that call (0x0206DEDA) at the routine, which then sits between every new Pokémon and hg-engine's function. In 1.0.9 those two lines sit inside 523DAA78 B089B5F0 … D0000000: only when the first word of hg-engine's CreateBoxMonData is where the routine calls it, so on any other build (1.0.4 included) the call is never pointed at the routine.

The routine has to know which Pokémon to change. Every function that makes a Pokémon passes a "fixed IVs" value, and 32 means "random IVs". The lines inside 52246C8C B0A8B5F8 … D0000000 (only while the field overlay that makes wild Pokémon is loaded, 0x02246C8C checked unchanged) change that 32 to 33 in the four calls that make wild Pokémon (0x022479EC, 0x02247AA6, 0x02247AF0, 0x02247B36), and the three lines after them change it to 34 in hg-engine's CreateStarter_CreateMon (0x023DCA9C, in overlay 129, checked at 0x023DCA700x023DCCA4, in overlay 129, checked at 0x023DCC78), which makes the starter you take from the lab's machine. Any value over 31 still means "random" to hg-engine. The routine turns 33 and 34 back into 32 (or 31, "all perfect", with Perfect IVs on), and only acts on Pokémon that came with one of them, so Pokémon made by any other call are left alone.

Each code's last D9…/D6…/D5…/D6… lines copy the DS's frame counter (0x027FFC3C) and the code's choice into its own 8 bytes of a table at 0x023D6300 every frame: the shiny code into slot 0, IVs 1, nature 2, gender 3, ability 4, species 5. The routine uses a choice only if its copy of the frame counter is less than 9 frames old, so a code you switch off stops acting at once, even though the call stays pointed at the routine until the game is reset. The table's 000M (the low half of the D5000000 line) says which Pokémon the code covers: 1 wild only, 3 wild and the starter.

The Pokémon's personality value decides its nature, its gender, its first or second ability and whether it's shiny. When a ticked code asks for one of these, the routine rolls personality values with the game's own random number generator (LCRandom) until one has everything that's asked for, keeping what the game chose itself (a Synchronize nature, a Cute Charm gender) when the matching code is off, and hands it to hg-engine's function as a fixed personality. So the game still builds the Pokémon, its checksum and stats itself.

Mega Evolutions and forms

A Mega Evolution only exists in a battle: its card says which Mega Stone it holds (or for Rayquaza the move it knows), and Moves shows what it learns as the Pokémon it comes from. A few Mega Evolve from a form of their own (Floette (Eternal Flower), Meowstic (Female) and Greninja (Battle Bond): their cards and the form's say so). Where the species card comes from

Base stats and types
The personal data above, as the game's GetMonBaseStat (0x0206FBE8) reads it: HP, Attack, Defense, Speed, Sp. Atk and Sp. Def at +0 to +5, the two types at +6 and +7 (the same one twice for a single type), the catch rate at +8 and the gender ratio at +0x10. Type names: message file 735.
Gender
The card's split is the game's own rule: female when the personality's lowest byte is below the species' ratio (so 127 gives ♀ 49.6%); 0 is male only, 254 female only, 255 genderless. hg-engine makes the females of Unfezant, Jellicent, Pyroar, Meowstic, Indeedee, Basclegion, Oinkologne a form of their own (a female-only entry; its GetBoxMonSex goes by the form), so their usual entry reads male only and the card says so in words.
a/0/0/4
The sprites (hg-engine's picture archive): six files per species, the female and male back and front pictures and the normal and shiny palettes. Each picture is 160 × 80, two frames side by side, 4 bits per pixel and scrambled with a running key; the card shows the first frame (the one battles show at rest), unscrambled, in the species' normal or shiny colours (the back uses the same palette). The card shows the male picture: 97 species look a little different as females, and a female-only species has only the female one. The pictures are in 16 sheets of 100 IDs (the Megas are on the sheets for IDs 1,001–1,100, 1,401–1,500 and 1,101–1,200), so a card loads only its own sheet (about 60 kB).
Other forms
Every form entry in the form table (a/0/2/8 member 11) that isn't marked to change back after a battle: 286. Each is an entry of its own, as hg-engine reads it (PokeOtherFormMonsNoGet): its stats, types, abilities and gender ratio (personal data), its evolutions (a/0/3/4 has a list for every entry), its level-up moves, TMs, tutor and egg moves (the same tables, at the entry). The names are hg-engine's own for the entries (its include/constants/species.h), checked against this ROM: every form entry the form table points at is named after the species whose list holds it. The pictures: 6 forms have Bulbasaur's files, and 27 the very pictures of their usual form (their cards say so); the rest their own.
