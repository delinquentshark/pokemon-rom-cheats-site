Pokémon Monomyth Field Guide

Cheat codes for the ROM hack Pokémon Monomyth, worked out from the game itself and tested in the mGBA emulator, plus look-ups for its items, moves, abilities, species (official Pokémon and the hack's own, with sprites, base stats and evolutions) and the wild Pokémon of every place.

Using a code in mGBA

  1. Open the cheats window. With the game running in mGBA, pick Tools → Cheats…
  2. Paste it and add it. Press Copy on a code in this guide, paste it into the box that says Enter codes here… and click Add New Code. Leave the code type on Autodetect.
  3. Tick it on, untick it off. A new code starts ticked, so it's already working. Untick it to switch it off. Double-click its name, (untitled), to rename it.

Before you start

  • Check it's the right game file. In mGBA, with the game running, open File → ROM info…: CRC32 should say 8441c61b. Anything else is a different version of Pokémon Monomyth: the codes won't work and could crash the game.
  • Back up your save. Copy the .sav file next to your ROM somewhere safe before trying codes. Every code here was tested for save damage, but a backup costs nothing.
  • Add each code on its own so you can switch them on and off separately. Don't add a "master code": mGBA doesn't need one, and one made for another game stops these codes working. If you already added one, remove all your cheats and restart mGBA.
  • Codes only work while they're ticked. Whatever you get while one is on (items, money, Pokémon, moves) is normal game data, so it stays after you untick the code and save.
  • Untick a code before you remove it. If you press Remove on a code that's still ticked, its effect can keep running until you restart mGBA.
  • mGBA remembers your codes, and whether each one is ticked, the next time you open the game. Untick the ones you aren't using.
  • Your game file is never changed. Codes change the game only in mGBA's memory, and only while they're ticked.

What's different in this game

Pokémon Monomyth is built on Pokémon Emerald's code, but a lot of what the codes touch works its own way. The codes on this page were made for it, so don't mix them with codes for Emerald or other hacks.

  • Most of its Pokémon are its own. Of its 404 species, 259 are the hack's own creations (fakemon) and 145 have the name of an official Pokémon. 38 of them are second, third… forms of another entry with the same name; the lists call those "Form 2", "Form 3" and so on, because the game doesn't name its forms. The Species tab can list just one kind.
  • Natures don't change stats. The summary screen still names a nature (from a list of 250, like "Dramatic"), but the game works out stats without it: two Pokémon with the same IVs and different natures have the same stats (tested). That's why there's no nature code, and no nature in the party editor.
  • Everybody gets EXP. A win or a catch gives EXP to every Pokémon in the party ("Everybody got their fair share!"), and the EXP boost multiplies each one's.
  • Three abilities. Almost every species (403 of 404) has a hidden ability, and Pick the ability can give it.
  • TMs aren't used up. A TM stays in the Bag after it teaches a move, and the Bag holds one of each.
  • Seven Bag pockets: Items, Medicine, PokéBalls, Battle Items, TMs & HMs, Berries, Key Items. Items stack up to 99 per slot (Berries 999), and the Bag starts a new stack when one is full.

How the codes were made and tested

Every code was worked out from this ROM: its code was disassembled to find where the game decides each thing (a new Pokémon's personality, IVs and ability, the money in the save, the move a TM teaches…), and each code changes that spot by patching instructions in mGBA's copy of the ROM. The catching codes add a small routine of their own in the ROM's empty space; the game still builds every Pokémon itself, checksum and all. Many of the game's own tables and functions sit in different places from Emerald's, and some work differently (its Pokémon data is scrambled with its own key, a Pokémon's shine is stored with it, abilities take two bits), so each one was found from the code that uses it.

Every code was then run in a headless build of mGBA 0.10.5, driving the game like a player: walks through the grass, the game's own event scripts, the starter's choice screen, a Poké Mart, a PC, the Bag and party menu, real battles and real Poké Ball throws. After each test the result was read from the game's memory, and anything saved was checked by saving with the codes on, unticking everything, resetting and pressing Continue: the Pokémon, items and money had to come back unchanged, with a valid checksum, no Bad Egg, and the game loading straight into the overworld. The ROM file's SHA-1 was the same after all testing.

Code formats

Encrypted
The codes you copy on this page are encrypted Action Replay (PAR v3) codes. mGBA reads them as Autodetect or Action Replay MAX.
Raw
Each code's raw (decrypted) form is in the Under the hood section of its tab, with the addresses it changes. Raw codes need Autodetect. Most are ROM patches: 00000000 18aaaaaa + 0000vvvv 00000000 puts the 16-bit value vvvv at address 0x08000000 + aaaaaa × 2.
Long codes
The catching codes are about 500 lines each, because each one carries the whole routine they share; a party edit is 136 to 180. Paste the whole code into one Add New Code. Ticking several catching codes at once is fine: they put the same routine in the same place, and mGBA keeps it while any of them is ticked.
In the browser
The page builds each code from your choices in codes.ts, a copy of the Python generator used for the tests. A check runs both on every code the page can make (42,555 codes, 806,390 lines: every species in every version, every gender, ability and IV code, every TM and move pair, every item, the EXP and egg codes, and a party edit for every species), and they match exactly. That check runs in Node.js. The page itself was tested in Chromium at desktop and phone widths, not in other browsers.
Remove while ticked
Unticking a code restores the original instructions. Removing a code that's still ticked leaves its patch in mGBA's memory (tested), so untick first; restarting mGBA clears it.

Type 0x42
A PAR v3 16-bit write through a pointer: 42 + the pointer's address, then the offset ÷ 2 and the value. The game moves its save data around in memory, so the code follows the pointer every frame instead of writing a fixed address.
0x089F15CC
Item table: 447 entries × 32 bytes; the name (+6) and pocket (+3) on this page come from it, and the pocket names from the ROM's list at 0x08A9DE64. The 439 items listed are the ones with a name; the ???????? and "Unused" entries are left out.

gSaveBlock1Ptr (the money and item functions read it). Vanilla Emerald uses 0x03005D8C.
+0x359C
PC item array: slots of {u16 item, u16 quantity}, stored plain (Bag quantities are XOR'd with the save's key).

Money

Money (SaveBlock1 + 0x494) is stored XOR'd with the save's key (SaveBlock2 + 0x40), so a plain memory write can't set it. The code changes the game's own money functions instead, and the game stores the maximum itself the next time it adds or takes some, key and all.

Money
GetMoney (0x080E6784) returns 9,999,999 (the literal already in AddMoney's pool at 0x080E67F0); IsEnoughMoney (0x080E67A4) always says yes, and with it special 0x8E (enough for the cost in var 0x8005?); RemoveMoney (0x080E67F4) stores what GetMoney said instead of subtracting (its subs at 0x080E6808 becomes a nop), and with it special 0x8F (take the cost in var 0x8005). AddMoney (0x080E67BC) isn't changed: it already caps at 9,999,999.

How each code works

Raw forms need Autodetect. For the codes that come in versions, the raw form shown is the version picked at the top of this tab. In the raw templates, the highlighted value is the one you'd change.

Always shiny

00000000 1802C312 00001C68 00000000 00000000 1802C313 00000780 00000000

This game keeps a Pokémon's shine with it: IsShiny (0x0805D2D4) says shiny when the usual shiny value (trainer ID halves XOR personality halves) is below 8, or when a 4-bit field of the Pokémon's own (box data 0x5C) equals a 4-bit "variant" worked out from its personality (0x0805D1D0); the value 15 means never shiny, and 19 species on a list at 0x085079C8 are never shiny. The creation routine, CreateBoxMon (0x080582F8), ends with the game's own "the next Pokémon is shiny" step: when a bit in the save (SaveBlock1 + 0x18CE, bit 4) is set, it calls 0x0805D250, which sets that field to the variant, and clears the bit. The two patches at 0x08058624 replace the bit test with a test of the Pokémon's original-trainer type, adds r0, r5, #1 / lsls r0, r0, #30, which takes that step for a Pokémon with you as its original trainer (wild, one-off battles, gifts, Eggs, and the starter and the one-off battles the game marks "never shiny") and not for trainers' Pokémon or ones made with another trainer's ID (in-game trades). The personality isn't touched; the field is saved with the Pokémon.

The routine the other four codes share

Perfect IVs, Pick the species, gender and ability all add the same routine (asm/catch.s, 484 bytes at 0x09FF0000, in the ROM's empty space). It has four entry points, and each code adds the jumps to the ones it needs (ldr r0, [pc] / bx r0 and the address, in place of a few of the game's instructions, which the routine runs itself before jumping back):

  • 0x080583EC, in CreateBoxMon just before it stores the personality: gender and ability (search a new personality).
  • 0x080585E0, where CreateBoxMon sets the ability number: IVs, the ability number, and a hidden ability.
  • 0x080B385E, the start of CreateWildMon, and 0x080EDA6C, of CreateScriptedWildMon (setwildbattle): the species.

Markers. The game calls CreateBoxMon with "random IVs" (32) for every wild, one-off and gift Pokémon. A marker changes that 32, at one call, to 33 (wild), 34 (one-off) or 35 (gift); to the game those still mean "random IVs". The IV, gender and ability parts act only on a call carrying a marker, and read a small table at 0x09FF0400, one slot for each kind: wild, one-off or gift. The Wild only version marks the wild callsWild + one-off version marks the wild and one-off callsbroadest version marks all three kinds and fills the wild slotthose two slotsall three slots.

What the routine does (each table entry 0xFFFF = not asked): IVs 31 sets all six IVs to 31 with the game's SetBoxMonData; for gender and ability it searches for a personality that has the ones asked for and keeps the one not asked for from the game's own first draw, keeping the personality's shiny value in the same block of 8 so a Pokémon that would have been shiny still is and one that wouldn't still isn't; a hidden ability is stored as ability number 2, after the game has set the usual one. Species that are always one gender or genderless skip the gender test. The species parts replace the species where the wild and one-off routines read it, so everything after (the Pokédex, the level, the game's own rules) sees your pick; gifts get theirs from patches in the givemon commands and the starter (below), not from the routine. The game then builds the Pokémon itself, checksum and all.

Wild only marks CreateWildMon's two calls (0x080B3902 for a Cute Charm gender, 0x080B3920), which every wild Pokémon goes through (grass, caves, water, fishing, Rock Smash, Sweet Scent), and takes its species at CreateWildMon's start. Catch on the first ball

00000000 180235CB 000046C0 00000000

In a trainer battle the Bag doesn't let you use a ball at all, so a throw never happens there. For a wild or one-off Pokémon, the ball-throw battle command (Cmd_handleballthrow, 0x0804670C) works out the catch odds in r6, and at 0x08046B94 does cmp r6, #0xFE / bls: up to 254, it rolls the shakes; above, it's caught at once, as with a Master Ball. The code turns that bls at 0x08046B96 into a nop, so every throw is caught at once.

How each code works

Edit a party Pokémon

The ROM's last part is empty (0xFF), and the catching codes' routine sits at 0x09FF0000. This code writes a small routine at 0x09FF8000, followed by a table: the species the code was made for (two bytes), the party slot, then one entry per field (the field, then the value as two bytes, low first), then 0. Its last two lines point the Start menu's POKéMON entry (the callback pointer at 0x08945544, normally 0x08099125) at the routine. So each time POKéMON is picked, the routine runs first: it reads the slot's species with the game's GetMonData (0x080576F0) and stops unless it's the one in the table (an empty slot reads as 0, so it never matches), skips an Egg, writes each field with the game's own SetMonData (0x08057F9C, which encrypts the Pokémon's data again and fixes its checksum, so it stays valid), calls CalculateMonStats (0x08056828), then goes on to the real callback and the party screen opens as usual. Unticking restores the pointer, so the routine is never reached again.

0x27–0x2C
SetMonData fields for the IVs: HP, Attack, Defense, Speed, Sp. Atk, Sp. Def (the game's own order).
0x1A–0x1F
EVs, same order.
0x2E
Ability number, two bits: 0 first, 1 second, 2 hidden. GetAbilityBySpecies (0x08059910) gives the ability in that slot even when the species has none there, so the page only offers the ones it has (for a missing one the code writes 0, its first).
0x20
Friendship, 0–255.
0x26
Poké Ball: five bits, the ball's item number (1 Master Ball … 30 Purple Ball; 29 and 31 are "UNOBTAINABLE" in the item list, so they're left out).
0x5C / 0xFF
Shininess. IsShiny (0x0805D2D4) says no when the Pokémon's 4-bit shine field (0x5C) is 15, and otherwise yes when the usual shiny value (trainer ID halves XOR personality halves) is below 8 or the field equals a 4-bit "variant" of the personality (0x0805D1D0), unless the species is on the game's never-shiny list (0x085079C8). Not shiny sets the field to 15. Shiny is field 0xFF, which isn't the game's: the routine calls the game's own 0x0805D250, which sets the field to the variant (what the game does for its own "next Pokémon is shiny"). The personality isn't touched either way.
0x0B / 0x2D
Species and is-Egg, read with GetMonData for the check.

EXP boost

After a win (or a catch), the battle command that gives EXP (0x0803407C) works out each party Pokémon's EXP with the game's own formula and bonuses (Lucky Egg, trainer battle, traded Pokémon: read from the code), then at 0x0803459E stores it plus 1 in gBattleMoveDamage (0x02025588), at most 65,535, for the battle screen to add. The code turns those seven instructions into a jump to a small routine at 0x09FF8300 (through a bx r0 already in the ROM, at 0x08033F84), which stores the amount shifted left by 1, 2 or 3 (×2, ×4, ×8; by 16 for Max, so any EXP becomes the most) instead, still at most 65,535, and jumps back. The battle screen adds it as an unsigned number (a test with 65,535 added 65,535), and level 100 still stops it.

One-shot kill

Battle script command 0x05 (Cmd_damagecalc; the command table is at 0x084F083C) calls the game's damage function (0x0802C8D8, with the move, the attacker 0x020255A1, the target 0x020255A2, its type and whether it's a critical hit) and stores the result in gBattleMoveDamage (0x02025588) at 0x0802FE7E. The code turns 0x0802FE7C–0x0802FE87 into a jump (ldr r1,[pc,#4] / bx r1 / two nops / the address) to a routine at 0x09FFA100 that does what those six instructions did, except that when the attacker is on the player's side (an even battler number), the target on the other (odd) and the game's damage is above 0, it stores 9999 instead: more HP than any Pokémon has. The game then takes the HP to 0 and the Pokémon faints as usual. A damage of 0 (an immunity, a status move) is left alone; misses never get here. Unticking puts every byte back.

PC from anywhere

The Start menu's entries are 16 bytes each from 0x08945530 (the name, then the callback); Exit is at 0x089455A0, with the callback StartMenuExitCallback (0x08099278: close the menu with 0x08099ED4, return "done"). When an entry is picked, the menu fades the screen to black unless its callback is Save, Exit or one of the two Retires (it compares them at 0x08099046), so the code keeps Exit's callback and changes its first eight bytes into a jump (ldr r3,[pc,#0] / bx r3 / the address) to a small routine at 0x09FFA000; nothing else calls it. The routine closes the menu the same way and starts a script with the game's ScriptContext_SetupScript (0x08090870), as the Safari Zone's Retire entry does. The script is three commands: lockall, setvar 0x40DF, 100, goto 0x0829A7F7, exactly what the game's map PCs do (their script at 0x0829A7D5): 0x0829A7F7 is the game's PC ("booted up the PC. Which PC should be accessed?", special 0xC8 for the menu, 0x39 for the PC Box Server, 0xBC for the player's PC), and 100 tells it there's no PC tile, so it skips the screen effect and the "PC off" tile (special 0x9F). Two more lines point the entry's name (0x089455A0) at "PC". Unticking puts every byte back.

Eggs hatch fast

The game counts steps in the Day Care data (SaveBlock1 + 0x349C + 0xAC); every 256 steps (the counter has to reach 255, checked at 0x0806071E) it takes egg cycles off each Egg in the party: one, or two with a Flame Body or Magma Armor Pokémon in the party (0x08061E00), and an Egg with none left hatches on the next round. Fast turns that check into a no-op, so it happens on every step: an Egg hatches on the step after its cycles run out (a Kotora Egg, 20 cycles: the 21st step). At once also sets the cycles straight to 0 (0x08060770 and 0x08060778), so it hatches on the second step.

How each code works

Change what a TM teaches

00000000 18558F78 0000MMMM 00000000

The game looks up each TM's move in a table at 0x08AB1EF0, 2 bytes per TM and HM item (TM01 is item 332, TM50 is 381, TM00 is 382, HM01 is 383, HM08 is 390), through ItemIdToBattleMoveId (0x08200F3C). The first line of the code points at the chosen TM's 2 bytes and the second line is the move ID to put there. While the code is ticked, mGBA writes that move ID into its copy of the game in memory; when you untick it, mGBA puts the original 2 bytes back. The Bag, the party menu and the teaching all read that one entry, which is why they all change together. Which Pokémon can learn a TM is a separate bit per TM in each species' data, so it doesn't change with the move.

MMMM is the move's 4-digit hex ID from the list (0001–02A7); the first line depends on the TM picked in the card.
