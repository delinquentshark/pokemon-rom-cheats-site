Perfect Emerald Field Guide

Cheat codes for the Pokémon ROM hack Perfect Emerald (version 8.6), worked out from the game itself and tested in the mGBA emulator, plus look-ups for items, moves, species and what each Pokémon learns in both movepools.

Using a code in mGBA

  1. Open the cheats window. With the game running in mGBA, pick Tools → Cheats…
  2. Paste it and add it. Press Copy on a code in this guide, paste it into the box that says Enter codes here… and click Add New Code. Leave the code type on Autodetect.
  3. Tick it on, untick it off. A new code starts ticked, so it's already working. Untick it to switch it off. Double-click its name, (untitled), to rename it.

Before you start

  • Check it's the right game file. In mGBA, with the game running, open File → ROM info…: CRC32 should say c0e39f8e. Anything else is a different version of Perfect Emerald: the codes won't work and could crash the game.
  • Back up your save. Copy the .sav file next to your ROM somewhere safe before trying codes. Every code here was tested for save damage, but a backup costs nothing.
  • Add each code on its own so you can switch them on and off separately. Don't add a "master code": mGBA doesn't need one, and one made for another game stops these codes working. If you already added one, remove all your cheats and restart mGBA.
  • Codes only work while they're ticked. Whatever you get while one is on (items, money, Pokémon, moves) is normal game data, so it stays after you untick the code and save.
  • Untick a code before you remove it. If you press Remove on a code that's still ticked, its effect can keep running until you restart mGBA.
  • mGBA remembers your codes, and whether each one is ticked, the next time you open the game. Untick the ones you aren't using.
  • Your game file is never changed. Codes change the game only in mGBA's memory, and only while they're ticked.

Your game's preset matters for two things

When you start a new game, Perfect Emerald asks for a game mode: Classic (the default), Modern or Custom. The codes were tested in a Classic game. The mode changes what some of the lists on this page show:

  • Which moves a Pokémon learns. Classic uses the original movepool; Modern (or Custom with PKMN MOVEPOOL on) uses the new one, with 14 new moves and new level-up, TM and egg moves. The Species tab shows either one: pick yours above the list.
  • A few abilities. In a Classic game, nine legendaries (Articuno, Zapdos, Moltres, Mewtwo, Raikou, Entei, Suicune, Lugia and Ho-Oh) have a different first ability, and Noctowl and Yanmega a different second one. The species list notes it next to their abilities.

How the codes were made and tested

Every code was worked out from this ROM: its code was disassembled to find where the game decides each thing (a new Pokémon's personality and IVs, the money in the save, the move a TM teaches…), and each code changes that spot by patching instructions in mGBA's copy of the ROM. The catching codes add one small routine of their own in the ROM's empty space; the game still builds every Pokémon itself.

Every code was then run in a headless build of mGBA 0.10.5, driving the game like a player: overworld Pokémon, walks through grass and caves, the game's own event scripts, a Poké Mart, the Game Corner, the Battle Frontier's exchange corner, a PC, the Bag and party menu, real battles and real Poké Ball throws. After each test the result was read from the game's memory, and anything saved was checked by saving with the codes on, unticking everything, resetting and pressing Continue: the Pokémon, items and money had to come back unchanged, with a valid checksum, no Bad Egg, and the game loading straight into the overworld. The ROM file's SHA-1 was the same after all testing.

Code formats

Encrypted
The codes you copy on this page are encrypted Action Replay (PAR v3) codes. mGBA reads them as Autodetect or Action Replay MAX.
Raw
Each code's raw (decrypted) form is in the Under the hood section of its tab, with the addresses it changes. Raw codes need Autodetect. Most are ROM patches: 00000000 18aaaaaa + 0000vvvv 00000000 puts the 16-bit value vvvv at address 0x08000000 + aaaaaa × 2.
Long codes
The catching codes are about 330 lines each, because each one carries the whole routine they share. Paste the whole code into one Add New Code. Ticking several of them at once is fine: they put the same routine in the same place, and mGBA keeps it while any of them is ticked.
In the browser
The page builds each code from your choices in codes.ts, a copy of the Python generator used for the tests. A check runs both on every code the page can make (23,169 codes, 542,675 lines: every species in every version, every nature, gender, ability, TM and move pair, and every item), and they match exactly. That check runs in Node.js. The page itself was tested in Chromium at desktop and phone widths, not in other browsers.
Remove while ticked
Unticking a code restores the original instructions. Removing a code that's still ticked leaves its patch in mGBA's memory (tested), so untick first; restarting mGBA clears it.

PC item code

42303C08 024CIIII 42303C08 024D03E7
IIIIItem hex ID from the list, always 4 digits (Rare Candy = 0044). 03E7Quantity, 999. Use a smaller hex value if you want less (e.g. 0063 = 99).

This is the raw (decrypted) form, so it needs Autodetect. The codes in the list are the same two lines, encrypted.

Type 0x42
A PAR v3 16-bit write through a pointer: 42 + the pointer's address, then the offset ÷ 2 and the value. The game moves its save data around in memory, so the code follows the pointer every frame instead of writing a fixed address.
0x08C807FC
Item table (pointer in the ROM header at 0x01C8): 399 entries × 44 bytes; names and pockets on this page come from it. The 343 items listed are the ones with a name; item 176, a second "Sitrus Berry" whose own ID field says 142, is left out.
0x03003C08
gSaveBlock1Ptr (the money, coin and flag functions read it). Vanilla Emerald uses 0x03005D8C.
+0x498
PC item array: slots of {u16 item, u16 quantity}, stored plain (bag quantities are XOR'd with the save's key).

Money, coins and Battle Points

Money (SaveBlock1 + 0x490) and coins (+0x494) are stored XOR'd with the save's key (SaveBlock2 + 0xBC), so a plain memory write can't set them. The codes change the game's own money and coin functions instead, and the game stores the maximum itself the next time it adds or takes some, key and all.

Money
GetMoney (0x08159F48) returns 9,999,999 (the literal already in AddMoney's pool at 0x08159FAC); IsEnoughMoney (0x08159F70) and special 0xCE (0x08159FCC, enough for the cost in var 0x8005?) always say yes; AddMoney (0x08159F94) and RemoveMoney (0x08159FBC) both branch to AddMoney's "cap at 9,999,999" store; special 0xCF (0x08159FF8, take the cost in var 0x8005) returns at once.
Coins
GetCoins (0x080BF070) returns 9,999; AddCoins (0x080BF0C0, 0x080BF0CA) stores 9,999; RemoveCoins (0x080BF122–0x080BF126) stores 9,999.
Battle Points
SaveBlock2 + 0xEC8, a plain u16. One type 0x42 line writes 9,999 there through gSaveBlock2Ptr (0x03003C0C) every frame.

Always shiny

The game's own creation routine, CreateBoxMon (0x08197F1C), has an "every encounter is shiny" mode of its own, behind flag 0x4A3: for a Pokémon with you as its original trainer, it redraws the personality until the shiny value is below 8 (shiny at every shiny-odds setting), keeping the nature. The first patch turns the flag check at 0x081980CE into a nop, so that path is taken for every Pokémon you get while the code is ticked; the flag itself, in your save, is never touched. The game's redraws change the personality's low half, which holds the gender and ability, so the other patches (0x081980EC–0x081980F4) make each redraw keep the low byte: the gender and ability the game or the other codes picked stay too. Trainers' Pokémon have another trainer as original trainer and don't take that path.

The routine the other five codes share

Perfect IVs, Pick the species, nature, gender and ability all add the same routine (asm/catch.s, 304 bytes at 0x09FF0000, in the ROM's empty space) and the same hook: CreateBoxMon's first instructions (0x08197F1E) become a jump to the routine, which does what it has to and then runs the instructions it replaced. Each code then adds a few "markers" and its own entries in a small table at 0x09FF0400.

Markers. The game calls CreateBoxMon with "random IVs" (32) for every wild, one-off and gift Pokémon. A marker changes that 32, at one call, to 33 (wild), 34 (one-off) or 35 (gift); to the game those still mean "random IVs". The routine acts only on a call carrying a marker, and reads the table slot for it: wild, one-off or gift. The Wild only version marks the wild callsWild + one-off version marks the wild and one-off callsbroadest version marks all three kinds and fills the wild slotthose two slotsall three slots.

What the routine does for a marked call, from its slot (each entry 0xFFFF = not asked): a species replaces the one passed in; IVs 31 makes the call "fixed IVs, 31" so the game fills every IV with 31; for nature, gender and ability it searches for a personality value that has all three of the ones asked for and keeps the ones not asked for from the game's own first draw (a Synchronize nature or a Cute Charm gender stays), then passes it in as a fixed personality. The search keeps the personality's shiny value in the same block of 8, so a Pokémon that would have been shiny is still shiny and one that wouldn't still isn't, at every shiny-odds setting; every nature can be found with any gender and ability, for every trainer ID (checked for all 65,536 cases). Species that are always one gender or genderless skip the gender test. The game then builds the Pokémon from those values itself, checksum and all.

Which Pokémon each version covers

Wild only marks CreateWildMon's two calls (0x08228AB0, 0x08228BAC), which every wild Pokémon goes through (overworld Pokémon, grass, caves, water, fishing, Rock Smash, Sweet Scent), and the two places where the game makes a wild Pokémon again to give it another shiny roll (chain fishing, 0x082298C6, and Sweet Scent, 0x082296B6). Wild + one-off adds the setwildbattle command's call (0x081E5C06) and the legendaries' event special 0x1E8 (0x081991A0). Wild, one-off + gifts adds the six calls in the givemon command (0x081E5956–0x081E5AE0), which the gifts and the starter use. Eggs, trainers' Pokémon and anything else the game makes go through other calls and are never changed by these five codes.

Catch on the first ball

00000000 1804B325 0000E017 00000000

The ball-throw battle command (Cmd_handleballthrow) refuses trainers' Pokémon before it works out any odds. For any other Pokémon it works out the catch odds in r1, and at 0x08096648 does cmp r1, #0xFE / bhi: above 254, straight to the "caught" branch (0x0809667C), as for a Master Ball; otherwise it rolls the shakes. The code turns that bhi at 0x0809664A into a plain b, so every throw takes the caught branch.

How each code works

Change what a TM teaches

00000000 1864F216 0000MMMM 00000000

The game looks up each TM's move in a table at 0x08C9E42C, 2 bytes per TM and HM item (TM01 is item 289, TM50 is 338, HM01 is 339, HM08 is 346). The first line of the code points at the chosen TM's 2 bytes and the second line is the move ID to put there. While the code is ticked, mGBA writes that move ID into its copy of the game in memory; when you untick it, mGBA puts the original 2 bytes back. The Bag, the party menu and the teaching all read that one entry, which is why they all change together. Which Pokémon can learn a TM is a separate bit per TM in each species' data, so it doesn't change with the move.

MMMM is the move's 4-digit hex ID from the list (0001–0170); the first line depends on the TM picked in the card.

Any Pokémon can learn any TM

00000000 180B94DF 000046C0 00000000

Before teaching a TM or HM, the party menu (0x08172940) asks CanMonLearnTMHM (0x081A065C) and stops with "not compatible" if the answer is no (beq at 0x081729BE). The code makes that branch a nop, so the answer is ignored and the menu shows Able! for everyone. No species' data is edited. Move tutors go through another branch of the same function, with their own list, and aren't affected.
